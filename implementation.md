# clack — Implementation Plan

> Mechanical keyboard sounds for every keypress, system-wide, on Linux and macOS.
> A single-binary Rust CLI that runs as a background service.
> Owner: **DarrylMathias** · License: **MIT** · Status: planning

This document is the source of truth for agents working on clack. Read **§1–§4** before picking up any work item in **§9**. If you need to change a decision in §2, flag it; don't silently diverge.

---

## 1. What we're building

A laptop keyboard sounds dull. clack plays a real mechanical keyboard recording (Cherry MX Blue, IBM Model M, HHKB…) through the speakers every time the user presses a key, in any app.

Inspiration: [The Listening Museum](https://sheets.works/data-viz/keyboard-sounds), a web gallery of 36 keyboards. It only makes sound inside a browser tab; clack makes it system-wide.

Prior art and why it isn't enough:
- **rustyvibes:** needs `cargo install`, needs soundpacks downloaded by hand and passed as a path, runs in the foreground, and is X11-only on Linux.
- **Mechvibes:** Electron, weak on Wayland.
- **Klack:** paid, macOS only.

### Goals
- **One-command install:** `curl … | sh`, no Rust toolchain needed.
- **Guided first run:** a short onboarding picks the default keyboard. After that the user never needs to think about clack again.
- **Every Linux distro and every macOS:** X11, Wayland (GNOME, KDE, Hyprland, Sway…), systemd or not.
- **Runs in the background:** starts at login and never ties up a terminal.
- **Packs are fetched by name:** users never download soundpacks or type file paths.
- **Instant toggle:** double-tap **Ctrl** to mute or unmute.
- **Imperceptible latency:** target < 20 ms from keypress to sound.
- **Private:** never stores or transmits keystrokes, and the README says so plainly.

### Non-goals (for now)
- Windows support. Don't design against it, but don't build or test for it.
- GUI or tray icon.
- Mouse click sounds.
- Filters on `clack list`.
- Per-application rules (Wayland doesn't reliably expose which window is focused).
- macOS code signing / notarization (no $99 Apple Developer account for now).

## 2. Decisions log

| # | Decision | Notes |
|---|---|---|
| D1 | **Rust**, single static-ish binary | |
| D2 | **Linux input = evdev** (`/dev/input/event*`) | Works identically on X11, every Wayland compositor, and TTY. No libinput, no compositor plugins. |
| D3 | **macOS input = listen-only `CGEventTap`** | Needs the Input Monitoring permission. Unsigned build for now. |
| D4 | **Audio = `cpal`** | No extra audio-backend abstraction on top; cpal already abstracts ALSA/PipeWire/Pulse/CoreAudio. |
| D5 | **Linux permission = udev `uaccess` rule** | Instant, no re-login. Fallback to the `input` group only on systems without logind/elogind. |
| D6 | **Background service** | systemd user unit, falling back to XDG autostart plus a detached spawn on Linux. launchd agent on macOS. |
| D7 | **Toggle = double-tap Ctrl** | Configurable. Short rising/falling tone as feedback. |
| D8 | **Packs are downloaded, not bundled in the binary** | The installer fetches only the binary. The **top-10 starter packs** are fetched during onboarding (see §6.4). Everything else is fetched on demand by `clack use <pack>`. |
| D9 | **`clack use <pack>` auto-installs** | If the pack isn't installed, it runs `pack add` first. |
| D10 | **`clack list` shows the whole catalog** | Installed and active packs are marked. |
| D11 | **Packs live in a separate repo: `DarrylMathias/clack-packs`** | Keeps sounds, licenses and credits together and the binary small. |
| D12 | **Only MIT / CC0 / GPL sound sources** | GPL packs are shipped as separate data files with their own LICENSE ("mere aggregation"), so clack stays MIT. |
| D13 | **Self-update via `clack update`** | Uses cargo-dist's `axoupdater`. |
| D14 | **Distribution via cargo-dist** | GitHub Releases plus a generated `curl \| sh` installer. |
| D15 | **Canonical keycode = Linux evdev `KEY_*` codes** | macOS and Mechvibes codes are translated into these. |
| D16 | **Same paths on both OSes** | Config in `~/.config/clack/`, data in `~/.local/share/clack/`. Simpler docs; respects `XDG_*` if set. |

## 3. User experience

### 3.1 Install

```sh
curl -fsSL https://github.com/DarrylMathias/clack/releases/latest/download/clack-installer.sh | sh
```

The installer (generated by cargo-dist):
1. Detects OS and architecture.
2. Downloads the binary and verifies its checksum.
3. Puts the binary in `~/.local/bin/clack` and makes sure that directory is on `PATH`.
4. Runs `clack setup`. All the clack-specific steps live in the binary so they can be re-run and tested.

### 3.2 `clack setup` (onboarding, runs automatically on first install)

```
  clack · mechanical keyboard sounds for your whole machine

  [1/4] Keyboard access
        clack needs read access to your keyboard to hear keypresses.
        It never records, stores, or sends what you type.
        → Installing udev rule (sudo password needed once)… ✓
  [2/4] Pick your keyboard   (↑/↓ to browse, type to hear it, Enter to choose)

      ▸ Cherry MX Blue (PBT)      clicky    ████ ready
        Cherry MX Brown (PBT)     tactile   ████ ready
        IBM Model M (1985)        buckling  ██░░ downloading
        …
      ┌ try it ───────────────────────────────┐
      │ the quick brown fox_                   │
      └────────────────────────────────────────┘
  [3/4] Start at login … ✓ (systemd user service)
  [4/4] Done. clack is running.

        Double-tap Ctrl to mute/unmute.   clack --help for everything else.
```

Notes:
- The picker reads keys **from the terminal itself** (crossterm raw mode), not from evdev. Previews therefore work even before the input permission takes effect, and on macOS before Input Monitoring is granted.
- While a row is highlighted, the demo auto-plays a short random burst (like The Listening Museum's "quick brown fox" demo). Typing in the box plays the pack live.
- On macOS, step 1 becomes: "macOS will ask for Input Monitoring. Click Open System Settings and enable clack." `clack setup` waits and polls until access is granted (or the user skips).
- `clack setup` is idempotent. `clack setup --reset` redoes everything.

|---|---|

| `clack volume [0-100]` | Sets the volume. With no argument, prints the current volume. |

### 3.5 Toggle behaviour (double-tap Ctrl)
- **What counts as a double-tap:** two **taps** of the same Ctrl key, left or right.
  - Each tap is press → release within **250 ms**.
  - The second press comes within **350 ms** of the first release.
  - **No other key** is pressed in between.
  - Auto-repeat events are ignored.
- **Works while muted:** the daemon keeps listening while muted; only playback is gated.
- **Feedback:** a short synthesized tone, rising (two notes up) for on and falling for off. It's generated in code, so it needs no asset, and it plays even when muted.
- **Persistence:** the mute state is saved to the state file and survives restarts.
- **Config:** `toggle = "double-ctrl" | "double-shift" | "double-alt" | "none"`. On Hyprland and similar, users can also bind `clack toggle` in their compositor.

## 4. Architecture

```
┌────────────────────────── clack daemon (one process) ─────────────────────────┐
│                                                                               │
│  input thread(s)             engine thread                 audio callback     │
│  ┌──────────────┐  KeyEvent  ┌──────────────────┐  PlayCmd  ┌──────────────┐   │
│  │ evdev (Linux)│──────────► │ toggle detector  │ ────────► │ voice mixer  │──►│ speakers
│  │ CGEventTap   │  crossbeam │ key → sample map │   rtrb    │ (no alloc,   │   │
│  │   (macOS)    │  channel   │ randomize pitch/ │  SPSC     │  no locks)   │   │
│  └──────────────┘            │ gain, mute gate  │           └──────────────┘   │
│                              └────────▲─────────┘                              │
│                                       │ ControlMsg                             │
│                              ┌────────┴─────────┐                              │
│                              │ IPC server       │ ◄── Unix socket ── clack CLI │
│                              └──────────────────┘                              │
└───────────────────────────────────────────────────────────────────────────────┘
```

- **One binary.** `clack daemon` is a hidden subcommand that runs the service in the foreground; the service manager is what backgrounds it. All other subcommands are thin IPC clients or local file operations.
- **The audio callback is sacred.** It never allocates, locks, logs, or drops an `Arc`.
  - Commands arrive over a lock-free SPSC ring (`rtrb`).
  - A pack switch sends a new sample bank; the old bank is sent **back** over a return ring and dropped on the engine thread.
- **Samples are decoded once, at pack load.** They become `f32` at the output device's sample rate (resampled at load time) and are held in memory. Packs are small (≤ a few MB decoded).
- **Keycode normalization happens in the input backend.** Everything past the backend sees evdev codes only (D15).

### 4.2 Core contracts (agree on these first; everything else codes against them)

```rust
// clack-core
pub type KeyCode = u16;                      // Linux evdev KEY_* value (D15)
pub enum KeyState { Down, Up }               // auto-repeat is filtered out in the backend
pub struct KeyEvent { pub code: KeyCode, pub state: KeyState, pub at: std::time::Instant }

// clack-input
pub trait InputBackend: Send {
    /// Blocks, pushing events into `tx` until `stop` is set. Handles hotplug internally.
    fn run(&mut self, tx: crossbeam_channel::Sender<KeyEvent>, stop: Arc<AtomicBool>) -> Result<()>;
    /// For `doctor`/`status`: keyboards we can currently read, or a typed permission error.
    fn probe() -> Result<Vec<DeviceInfo>, AccessError>;
}
```

The IPC protocol is newline-delimited JSON over a Unix socket at `$XDG_RUNTIME_DIR/clack.sock` (fallback: `~/.local/state/clack/clack.sock`). Messages:

```json
{"cmd":"status"} {"cmd":"toggle"} {"cmd":"set_muted","muted":true}
{"cmd":"use","pack":"ibm-model-m"} {"cmd":"volume","value":60} {"cmd":"reload"} {"cmd":"shutdown"}
→ {"ok":true,"status":{...}} | {"ok":false,"error":"..."}
```

## 5. Component specs

### 5.1 Linux input (`clack-input/linux.rs`)
- **Device discovery:** enumerate `/dev/input/event*` with the `evdev` crate. Keep devices that report `EV_KEY` with `KEY_A`…`KEY_Z` and `KEY_SPACE`. This excludes mice, power buttons, and lid switches.
- **Reading:** open read-only and **never grab** (`EVIOCGRAB`), so we observe keys without stealing them. Use one thread per device, or `epoll` over all devices.
- **Event filtering:** `value` 1 = Down, 0 = Up, **2 = auto-repeat → drop**.
- **Hotplug:** watch `/dev/input` with `inotify` for USB and Bluetooth keyboards. Add new devices; remove devices on `ENODEV`.
- **Permission errors:** return typed errors (`AccessError::PermissionDenied { device }`) so `doctor` can explain them.

### 5.2 macOS input (`clack-input/macos.rs`)
- **Event tap:** `CGEventTapCreate` with `kCGEventTapOptionListenOnly` on `keyDown | keyUp | flagsChanged`, run on its own CFRunLoop thread. Use the `core-graphics` / `core-foundation` crates.
- **Modifiers:** Ctrl, Shift, Cmd, etc. arrive as `flagsChanged` events. Derive Down/Up by diffing the flags.
- **Auto-repeat:** drop events where `kCGKeyboardEventAutorepeat` is set.
- **Keycodes:** map macOS virtual keycodes (`kVK_*`) to evdev codes with a static table in `clack-core/keymap.rs`.
- **Permission:** `CGPreflightListenEventAccess()` checks it; `CGRequestListenEventAccess()` triggers the prompt.
- **Tap timeouts:** handle `kCGEventTapDisabledByTimeout` by re-enabling the tap.
- **Known limitation (unsigned binary):** the permission is lost when the binary changes (every update). `update` and `doctor` must handle this (§5.11, §5.12).

### 5.3 Keymap (`clack-core/keymap.rs`)
- `macos_vk_to_evdev(u16) -> Option<KeyCode>`.
- `mechvibes_to_evdev(u32) -> Option<KeyCode>`. Mechvibes uses libuiohook `VC_*` codes, which are PC set-1 scancodes. **Basic keys are identical to evdev** (e.g. A = 30, Space = 57). **Extended keys differ** (e.g. `VC_UP` = 0xE048 = 57416 vs `KEY_UP` = 103), so they need an explicit table.
- Unit test: every key on a standard ANSI/ISO layout round-trips.

### 5.4 Pack format (`clack-core/pack.rs`)

On disk: `~/.local/share/clack/packs/<id>/`

```
manifest.toml
sound.ogg            # sprite mode: one file with time ranges
# or sounds/*.ogg    # multi-file mode
LICENSE
```

`manifest.toml`:

```toml
format = 1
id = "cherry-mx-blue-pbt"
name = "Cherry MX Blue (PBT)"
family = "clicky"               # clicky | tactile | linear | topre | buckling | typewriter | other
license = "MIT"
source = "https://github.com/hainguyents13/mechvibes"
credits = "Mechvibes contributors"

sprite = "sound.ogg"            # omit for multi-file mode

# A value is a sprite range [start_ms, dur_ms], a file path, or an array of either (random pick).
[press]
default = [[0, 90], [120, 90], [240, 90]]
57 = [2000, 110]                # space (evdev code)
28 = [2300, 120]                # enter
14 = [2600, 95]                 # backspace

[release]                        # optional; no release sounds if absent
default = [[3000, 60]]
```

- **Lookup order:** `press[code]` → `press.default`. The same for release.
- **Randomization:** random pick from arrays, pitch ±3% (playback rate), gain ±10%. Tunable in the config (`humanize = true`).
- **Mechvibes importer:** `pack add` converts a Mechvibes `config.json` (both `key_define_type: "single"` sprite and `"multi"` file packs) into `manifest.toml` at install time, translating keys through §5.3. The runtime only ever reads the native format.
- **Decoding:** `symphonia` handles OGG Vorbis, MP3, WAV and FLAC. Resample with `rubato` or plain linear interpolation (fine for clicks) to the device rate.

### 5.5 Audio engine (`clack-core/mixer.rs`)
- **Stream setup:** open the default output with `cpal`, asking for a small buffer (`BufferSize::Fixed` of about 128–256 frames where supported). Fall back to the default buffer size.
- **Voices:** fixed pool of **32**; steal the oldest voice when full. Each voice holds `(bank_idx, sample_idx, position (f64), rate, gain)`.
- **Master gain:** volume 0–100 mapped on a perceptual curve (`(v/100)^2`).
- **Device changes:** on a stream error (headphones unplugged, default device changed), rebuild the stream on the engine thread.
- **Linux audio stack:** cpal uses ALSA, which reaches PipeWire / PulseAudio through their ALSA plugins on essentially every desktop distro. Verify on the test matrix (§8).

### 5.6 Daemon (`clack/src/daemon.rs`)
- **Startup:** load config → load the active pack → start audio → start input → start the IPC server.
- **Single instance:** lock file / socket bind; a second daemon exits cleanly.
- **Logging:** to `~/.local/state/clack/clack.log` (`tracing`, rotated, warnings and errors by default). **Never log key codes**, even at debug level. There is a CI grep test for this (§8).
- **Signals:** SIGTERM → graceful shutdown; SIGHUP → reload config and pack.

### 5.7 Service management (`clack/src/service.rs`)

| Platform | Mechanism |
|---|---|
| Linux + systemd | `~/.config/systemd/user/clack.service`, `systemctl --user enable --now clack` |
| Linux, no systemd (Void, Alpine, Artix, Gentoo-OpenRC…) | `~/.config/autostart/clack.desktop` (XDG autostart), plus `clack start` spawning a detached daemon (`setsid`, double-fork, stdio → log) |
| macOS | `~/Library/LaunchAgents/dev.clack.plist`, `launchctl bootstrap gui/$UID …`, `KeepAlive` |

- `start` / `stop` / `restart` go through whichever mechanism is installed.
- **Window managers that ignore XDG autostart** (Hyprland, Sway, i3, dwm… when systemd user services aren't used): `doctor` and `setup` print the one line to add, e.g. `exec-once = clack start`.

### 5.8 Linux permission setup (`clack/src/perms.rs`)

`assets/70-clack.rules`:

```
SUBSYSTEM=="input", KERNEL=="event*", ENV{ID_INPUT_KEYBOARD}=="1", TAG+="uaccess"
```

1. Install it with `sudo install -m644 … /etc/udev/rules.d/70-clack.rules`. The number **must be < 73**, because `73-seat-late.rules` is what applies `uaccess`.
2. Then run `sudo udevadm control --reload && sudo udevadm trigger --subsystem-match=input --action=change`.
3. Verify by calling `InputBackend::probe()`. Access works **immediately**, with no re-login.

Special cases:
- **No logind/elogind** (so `uaccess` does nothing): fall back to `sudo usermod -aG input $USER`, and tell the user a re-login is required.
- **NixOS** (`/etc` is read-only): don't write anything. Print the `services.udev.extraRules` snippet for `configuration.nix`.
- **Security note** (goes in PRIVACY.md and the setup text): this lets processes running as the logged-in user read keyboard events. That's the same trust level as X11 had by default. `uninstall` removes the rule.

### 5.9 Pack manager & catalog (`clack/src/packs.rs`)
- **Catalog:** `index.json` from `https://github.com/DarrylMathias/clack-packs/releases/latest/download/index.json`. Cached at `~/.local/share/clack/index.json`, refreshed when older than 24 h or on `list` / `use` if a fetch is possible. Offline → the cached copy is used silently.

  ```json
  { "format": 1, "packs": [
    { "id": "ibm-model-m", "name": "IBM Model M (1985)", "family": "buckling",
      "license": "GPL-2.0", "starter": true, "size": 812345, "sha256": "…",
      "url": "https://github.com/DarrylMathias/clack-packs/releases/download/packs-v1/ibm-model-m.tar.gz",
      "blurb": "The 1985 buckling-spring original. Loud, proud, indestructible." } ] }
  ```

- **Install:** download → verify sha256 → extract to a temp directory → validate the manifest → atomic rename into `packs/`. HTTP via `ureq` (rustls), extraction via `flate2` + `tar`.
- **`pack add` input types:** catalog id, `https://` URL (tar.gz / zip), local folder, or Mechvibes zip/folder (auto-detected by `config.json`).
- **`use <pack>`:** installs it if missing → writes `default_pack` to the config → sends IPC `use` to the running daemon.

### 5.10 Config (`~/.config/clack/config.toml`)

```toml
default_pack = "cherry-mx-blue-pbt"
volume = 70            # 0–100
toggle = "double-ctrl" # double-ctrl | double-shift | double-alt | none
release_sounds = true
humanize = true        # random pitch/gain variation
```

Runtime state (the muted flag) lives in `~/.local/state/clack/state.toml`, not in the config.

### 5.11 `clack doctor`

Prints a ✓ / ✗ / ! line for each check, each with an exact fix command:
- Binary on `PATH`; version (and newer version available?).
- Config parses; the active pack exists and its manifest is valid.
- Service installed and running; IPC responding.
- **Input access:**
  - Linux: list readable keyboards. If there are none: is the udev rule present? is `uaccess` applied (`getfacl /dev/input/eventN`)? is logind present? is this NixOS?
  - macOS: preflight access. If it's missing, offer to open `x-apple.systempreferences:com.apple.preference.security?Privacy_ListenEvent`.
- Audio: default output device found, the stream opens, and a latency estimate is shown.
- Autostart: detects WMs that need an `exec-once` line.

### 5.12 `clack update`
- Uses `axoupdater` (cargo-dist's updater): check the latest GitHub release → download the binary → verify → atomically replace the binary → restart the service.
- **macOS:** warn before the update and verify after it. The Input Monitoring grant will likely reset; walk the user through re-enabling it (the same flow as setup step 1).
- Also refreshes the pack catalog.

### 5.13 `clack uninstall`
- Stops and removes the service.
- Removes the udev rule (sudo) and reloads udev.
- Removes the binary.
- Asks: "Delete packs and config too? [y/N]".

### 6.3 Pack build pipeline (in `clack-packs`)
- `packs/<id>/source.toml` records the upstream URL, commit, license, and conversion notes. A script (`build.py` or a small Rust tool) fetches upstream → converts to the native `manifest.toml` → **re-encodes to OGG Vorbis ~q3, mono, 48 kHz** → writes `LICENSE` → produces `<id>.tar.gz` and `index.json` with sizes and sha256s.
- **Size target:** Mechvibes sprites are about 2.5 MB each today; aim for **≤ 1 MB per pack** after re-encode and trimming silence, so the whole starter set is ≈ 10 MB.
- **Bucklespring:** 209 per-key WAVs → a multi-file pack (or merge into a sprite). Filenames already map to evdev codes.
- CI publishes a `packs-vN` GitHub release on tag.

### 6.4 How D8's "light install" and "top-10 preinstalled" fit together
- **The installer downloads only the binary** (a few MB).
- **When onboarding opens, the 10 starter packs download in parallel in the background** (≈ 10 MB total). The picker shows per-pack progress, and each pack becomes previewable as soon as it lands.
- **The chosen pack is guaranteed present** before setup finishes. If the network is too slow, setup can finish with only the chosen pack and fetch the rest lazily.

## 8. Testing

- **Unit tests (clack-core):**
  - keymap tables
  - manifest parsing and Mechvibes conversion (fixtures for single and multi packs)
  - toggle detector (timing cases: slow taps, a key in between, repeat, left + right Ctrl mix)
  - mixer (voice stealing, gain, no allocation in `render()`, checked with a counting allocator in tests)
- **Integration tests:**
  - IPC round-trip against a daemon running with a **null audio sink** and a **fake input backend** (the `InputBackend` trait makes this easy)
  - pack install from a local tarball
- **Privacy guard:** a CI test fails if any `tracing` / `println` call site formats a `KeyEvent` or `KeyCode` (grep lint plus code review rule).
- **Latency:** a manual check with a `--measure` debug flag on the daemon that logs input-timestamp → buffer-write delta (aggregate stats only, never codes). Target p95 < 20 ms.
